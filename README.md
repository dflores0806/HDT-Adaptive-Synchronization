# Adaptive Digital Twin Synchronization — Experiments

Runnable experiment code for a containerized edge–middleware–cloud digital-twin synchronization prototype. This repository contains the middleware, synthetic edge agents, constrained synchronization controller, fixed experimental campaign, unit tests, and metric reconstruction scripts. It **does not** include manuscripts, figures, generated results, or archived runs.

## Experiment design

A fixed, deterministic plan contains **63 runs**: 3 calibration/capacity gates, 36 scalability trials (4, 8, 16, or 32 agents), 6 ablations, 9 HTTP-impairment trials, and 9 trials with 50% node churn. The controller evaluates reporting intervals and participating nodes against age/error, communication, energy-proxy, latency, and subsystem-coverage constraints. Reference signals are used for **offline** evaluation only.

Experiments run on a **single Docker host**. Delays and dropped operations are application-level injections, not real WAN packet loss; source data are synthetic. Throughput and byte accounting represent accepted operational HTTP payloads rather than total IP traffic or physical energy use.

## Requirements

- Ubuntu 24.04 or similar Linux with Python **3.11–3.12**, `python3-venv`, `pip`, `tmux` and `flock` (`util-linux`).
- Docker Engine with Docker Compose v2 plugin; at least **4 logical CPUs and 6 GiB RAM** for the 32-agent capacity gate. A dedicated machine is recommended.
- Network access for installing pinned Python dependencies and pulling container images.

Docker commands require permission to use the daemon socket. Membership in the `docker` group grants root-equivalent privileges. Run only in a trusted, isolated experiment environment; the default PostgreSQL credentials are for **local testing**, not production deployment.

## Setup

```bash
sudo apt update
sudo apt install -y python3-venv python3-pip tmux unzip
bash prepare_ubuntu_v13.sh
```

If Docker is not available, install and configure Docker Engine and Compose following the official Docker instructions, then reconnect your SSH session after any group-permission changes. The provided `install_docker_ubuntu.sh` is optional; review it before running as it requires elevated privileges.

## Verify and run

```bash
# Unit tests (77 tests in the frozen environment)
.venv/bin/python -m unittest discover -s research/tests -v

# Review the fixed 63-run plan without starting Docker
.venv/bin/python research/final_campaign_v13.py

# Optional isolated capacity gate at 32 agents
./start_ubuntu_v13.sh capacity
./status_ubuntu_v13.sh

# Full 63-run campaign in a detached tmux session
./start_ubuntu_v13.sh final
./status_ubuntu_v13.sh
```

You can disconnect SSH after the `tmux` session starts. Use `tmux attach -t iotj13_campaign` to inspect the live session (detach with **Ctrl+B**, then **D**). Do not start parallel runs from the same checkout.

By default, the application binds its exposed ports to the loopback interface. Values may be configured using `HDT_API_PORT`, `HDT_PG_PORT`, `HDT_MQTT_PORT`, and `HDT_COMPOSE_PROJECT`. Inspect `.env.example` for the remaining experiment defaults.

## Analyze a completed campaign

The launcher writes the run directory under `campaigns_v13/` and a compressed results archive at the repository root. To regenerate the summary tables from either an archive or a run directory:

```bash
.venv/bin/python research/final_report_v13.py   campaigns_v13/<campaign-directory> --out analysis
```

The outputs include per-run quality, comparisons by fidelity ceiling, time-window summaries, and churn recovery measures. Campaigns that fail quality gates remain in the archive and are not silently treated as successful trials.

## Reproducibility notes

Experiment configurations and pairing are fixed in `research/final_campaign_v13.py`, including the random seed, workload variations, boundaries, and quality checks. `research/final_report_v13.py` reconstructs numerical summaries from newly generated results. Files generated by running experiments are deliberately excluded from Git via `.gitignore`.

To reproduce the **previously recorded observations** without rerunning experiments, their original raw result archive is required; it is **not** part of this code-only repository. Figures and publication materials are also intentionally excluded.

No external-source or production sensor data are included. No license has been selected for this archive; choose a license before granting reuse rights.
